### 1. 默认行为与编译影响

普通 Compile 与 Compile Check 默认执行素材存在性检查，对相同输入与文件观察结果应用同一诊断政策。普通 Compile 在本次检查及其他验证通过后才可发布；Compile Check 继续不写 Generated Project Data、不更新 Sync Manifest 或刷新 Generated Freshness。

存在 error 时本次编译失败，不发布新的 Compile Output；只有 warning 或信息停止点不会因素材政策而失败。不得删除指令、修改素材名称、丢弃非活动保存配置、替换文件或重写外部项目数据来消除诊断。既有发布失败、同步状态和 Project Root 写入隔离继续适用，不承诺额外的旧输出保留机制。

覆盖沿用[事件直接与间接素材依赖的检查边界如何统一](02-direct-asset-reference-coverage.md#answer)，文件事实沿用[素材文件存在性应如何判定](03-asset-file-existence-contract.md#answer)。正式 DSL、可识别原生 Raw DSL Command、直接和已选间接来源使用同一政策，不能用 raw 改写绕过。未知脚本、插件或 raw payload 的既有不解释边界不变；其原有诊断也不会被本票的信息政策取消。

### 2. 严重性矩阵与优先关系

| 事实结果 | 普通明确素材使用 | Conditional Asset Candidate 或明确非活动保存配置 | Asset Check Exception 能否降级 |
| --- | --- | --- | --- |
| 已确认所需文件／目录缺失 | error | warning | 可以，将适用 error 降为 warning |
| 已确认准确名称／大小写不符 | error | warning | 可以，将适用 error 降为 warning |
| 已确认路径／文件类型不符合 | error | warning | 可以，将适用 error 降为 warning |
| 不支持的名称形式 | error | error | 不可以 |
| 素材路径包含不支持的符号链接／junction | error | error | 不可以 |
| 相应使用类别处于不支持的加密模式 | error | error | 不可以 |
| 所需目录／元数据无法访问或查询失败 | error | error | 不可以 |
| 必需字段缺失、类型错误或必要字段无法解释 | error | error | 不可以 |
| 观察到查询前后矛盾，无法确认本次结果 | error | error | 不可以 |
| 覆盖契约允许的动态未知或循环停止 | 信息记录，不制造素材 warning/error | 同左 | 不适用 |
| 合法原生 None | 不产生文件查询或缺失诊断 | 同左 | 不适用 |
| 准确目标经元数据确认是普通文件 | 本次文件存在性通过 | 同左；保留候选／非活动条件 | 不需要降级 |

只有前三类已确认文件问题适用候选／非活动 warning 和逐素材降级。支持边界、必要输入和检查可信度错误优先，不因保存配置关闭或存在例外而降级。System 加密标志的解释仍只针对存在相应待检查素材使用的类别，不扩大为无关类别校验。

非活动状态必须能由明确保存开关或模式确认，例如非 custom 自主移动模式中保留的 Movement Route；不能根据页条件、分支可达性、命令可能不执行等运行时推演降级。Conditional Asset Candidate 仅指覆盖契约已选的初始／默认关系，并保留其适用条件；一般运行条件不自动将普通固定名称改成候选。两种 warning 条件同时成立时仍保留两种依据，不改变原始保存状态。

固定 Project Data Reference 缺失及既有 DSL 结构、值域、Script Command Gate 错误继续按原契约处理，不改称文件缺失，也不受素材例外影响。单纯修改 Actor HP 等未入选素材关系的操作不得引出该条目的全部图像错误。尺寸、内容可读性、解码和播放均不纳入；元数据确认存在不等于可加载或必然执行。

### 3. 逐素材例外与配置有效性

Asset Check Exception 是 Workspace 中对一个准确素材类别与原始名称的显式政策，必须有原因。它只将矩阵前三类问题的 error 降为 warning，不停止查询、不隐藏问题、不把结果改成存在。相同目标的全部独立使用都适用，包括正式、已识别 raw 和间接来源；每次使用仍保留自己的基础级别、有效级别、条件、例外及原因。

匹配不 trim 名称、不折叠大小写、不规范化、不 URL 解码、不剥除看似扩展名的后缀。类别非法、名称为空、原因缺失或仅有空白、同一类别与名称重复声明均为配置 error；不以最后一项覆盖前项。首版没有全局关闭、全部 warning、通配符或逐事件／逐位置例外。

相关检查完整完成后，如果某条例外没有使任何 error 降为 warning，产生指向该配置项的“例外当前未产生降级”warning，例如素材已补齐、当前事件不再使用，或全部使用本来就属于 warning。检查未完成、无法确定实际作用时不作无用例外结论。不自动删除或修改例外；它不构成文件存在或运行成功的证明。

### 4. 逐次诊断、搜索依据与完整来源

每处诊断保留稳定问题标识、编译阶段、具体原因、基础与有效严重性，以及适用的候选／非活动条件和例外原因。原生文件事实必须能区分缺失目录、缺失文件、名称不符、类型问题、不支持形式、无法检查、无法确认和必要数据解释错误，不把这些都压成“找不到素材”。

保留素材类别、原始名称、所用 Project Root、准确类别目录、追加扩展名、支持的目标相对路径及具体失败位置；如果已有仅大小写不同项，可保留为解释线索但不选择替代。对不支持名称不作路径穿越解析，不编造一个已安全查询的目标。关联必要输入问题携带具体标准数据字段；公共字段或目录错误保留受影响的全部已知使用，而非伪造许多已确认缺失文件。

逐次来源包括事件类型与 Entry Identity、页、命令、嵌套 Child Command Body、Movement Route 和素材字段／原生参数位置；间接使用还包括完整 Asset Dependency Chain、标准数据类别、条目 ID、字段及每步关系依据。Common Event 关系保留每个调用位置与有界链，不能通过复用结果丢掉其他起点或调用来源。DSL 对象路径和可靠的 Definition Source 位置可以附带；只有可靠时才提供源码文件行列，不能将对象路径冒充源码位置。

动态未知与循环停止记录发生位置、原因和已有关系链，并明确该路径未被继续展开；不当成 None、无依赖或文件存在性通过。合法 None 不制造空名 Asset Reference；省略字段仍先采用既有 Compiler Default，再按最终保存值处理。

### 5. 分组、统计与检查完整性

默认按目标文件与问题类别分组，组内列出全部独立使用及来源链。组内只要有有效 error，组就标为 error；各处保留自己的级别和例外判定，不能以候选 warning 或一处结果覆盖另一处普通 error。对于没有合法文件目标的支持／输入／I/O 问题，按具体失败依据关联来源，不凭空制造文件路径。

摘要分别统计问题文件／问题组与受影响使用次数；同一目标的多个问题组不应被误称多个不同文件，无法形成合法目标的组也不计为已确认缺失文件。原生路线主记录和镜像仍算一次逻辑使用；实际不同字段、指令或调用来源不能因相同文件名被去重掉。

发现 error 后继续完成其他可安全、独立进行的素材检查，最后统一输出结果并判定失败。某条必要关系损坏时只停止受影响路径；目录失败不阻止其他可查类别。报告明确未运行／未完成的部分与原因；更早的配置、结构或项目验证已阻止建立可信检查输入时，不强行分析残缺数据，不承诺穷尽所有素材问题。已得到的 warning 与 error 均应保留在报告中，不能因最终失败而静默丢掉。

### 6. 完成边界与交接

本票只确定诊断内容、严重性、逐素材例外、分组和 Compile／Compile Check 的政策，不实现文件扫描、配置字段、报告接口或产品修复。既有实现并不具备完整素材报告；本契约不把现有共享编译路径等同于实现完成，也不增加通用诊断框架或额外 JSON CLI 的承诺。

- [素材检查如何接入 Compile 与 Push 并保持结果有效](05-workspace-asset-check-lifecycle.md)负责标准数据版本（含加密标志）、实时文件检查点、输入变化机制、缓存、Compile Baseline／Generated Freshness、Diff／Push 及接管步骤。本票的 error 政策不能替代这些一致性决定，也不将素材纳入快照、复制或 Push 写入范围。
- [如何验收素材存在性检查并交接实施规格](06-asset-validation-acceptance.md)负责按已定政策设计独立预期、自动化与必要原生核对，包括候选／非活动、raw、例外与不完整报告。本轮源码只读核查不是产品测试通过或媒体加载验收。
- 保持 ADR 0011／0012 的保存值、已识别 raw 和外部数据所有权边界，并以本票显式严重性规则细化有限文件扫描政策；不得再用“受支持保存值”推导素材检查必然非阻断。对有效保存状态因文件支持边界而不能编译的情况明确报错、保留原值，不补修。ADR 0013 的工作流修订留给后续票。
