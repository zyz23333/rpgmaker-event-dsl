## Question

前置输入：[MV 原生素材名称如何定位到项目文件](01-native-asset-file-resolution.md)与[事件直接与间接素材依赖的检查边界如何统一](02-direct-asset-reference-coverage.md)。

基于原生定位研究与已定依赖覆盖，首版怎样把直接 Asset Reference 以及从标准项目数据提取的间接素材类别和 filename stem 判定为存在、缺失或无法确认？

选择检查依据为哪种 Project Root 文件树，明确图片、音频、影片所需的文件候选与扩展名规则、大小写及名称的准确匹配、子路径和目录边界、同名多候选，以及目录、不可读文件、符号链接或链接逃逸的处理。明确是否支持部署/加密素材，不能因为原生支持某种形式就自动把它纳入本工具支持承诺。

对映射到同一原生素材类别和名称的直接与间接来源，明确文件匹配规则的一致性，并保留各自来源。区分标准数据条目缺失、必要素材字段无法解释、字段合法地不指定素材和实际文件缺失；不把原生空名称直接构造成无效 DSL Asset Reference，也不将其统一视作缺失文件。

判定结果不能依赖未声明的运行平台或把“存在一个文件”写成可播放保证。锁定命名/路径规则与失败分类，不自动重命名、复制、修复素材或改写原生保存名称。

### 1. 检查对象与项目边界

以[事件直接与间接素材依赖的检查边界如何统一](02-direct-asset-reference-coverage.md#answer)和 ADR 0016 已定的 Event Asset Use 为输入。直接 Asset Reference、已识别原生 raw 参数及有限标准项目数据关系最终得到的相同类别和原始名称，使用一致的文件规则；Conditional Asset Candidate 的适用条件不改变文件匹配方式，也不等同于运行时必定使用。

首版只支持 Windows / RPG Maker MV 1.6.1 的普通编辑 Project Root。使用 Workspace 已解析和绑定的根，不自动进入 `www/`、切换部署目录、寻找其他资源根或使用加密包替代普通文件。Project Root 本身的有效性继续遵守既有 Workspace 契约；本票不增加部署模式，也不宣称能自动识别所有伪装成普通项目的部署树。

类别目录、原生名称及覆盖关系由已定覆盖契约提供，不按“发现某个文件”反向扩展检查范围，不扫描无事件关系的全库素材。素材文件来自 Project Root 文件树；标准数据输入版本、具体读取时机与同步一致性由工作流议题决定。

### 2. 唯一目标文件与准确匹配

| 类型 | 原生类别目录（相对 Project Root） | 追加扩展名 |
| --- | --- | --- |
| 图片 | `img/<原生图片类别>/`，仅使用覆盖契约选定的类别 | `.png` |
| BGM / BGS / ME / SE | `audio/bgm/`、`audio/bgs/`、`audio/me/`、`audio/se/` | `.ogg` |
| 影片 | `movies/` | `.webm` |

这是固定的 Windows 桌面文件要求，不是宿主浏览器媒体能力探测。原始保存名称直接追加扩展名，不剥掉已有后缀：`Forest.png` 对应 `Forest.png.png`。`.m4a`、`.mp4`、加密后缀和其他格式不能替代所需文件，也不增加格式配置或缺失回退。

Project Root 以下的类别目录、名称、扩展名均要求大小写准确匹配。不 trim、不做大小写折叠、Unicode 规范化、URL 解码或名称修复。根路径本身继续使用现有 Project Root Binding；不把素材的准确匹配政策外推为修改根绑定的 realpath／大小写规则。

准确项存在且满足其他条件时通过；同目录另有大小写变体或其他格式不构成歧义。没有准确项、只有一个或多个仅大小写不同的项时，记录名称不匹配，不任选一个替代。近似项只可作为解释线索，不构成成功匹配，也不授权跨目录搜索或跟随链接。

### 3. 名称形式与类别差别

只支持类别目录直接包含的单层文件名；含 `/`、`\`、绝对路径形式或路径穿越的名称不作路径解析，记录为不支持的名称形式。保存原始值，不改变既有 DSL／原生保存值的表达能力。

按追加扩展名后的完整文件名应用普通 Windows 文件名规则。普通中文、空格、点号和原生 `$`／`!` 前缀按原样匹配；非空纯空白名称不当成 None。stem 自身以空格或点结尾不自动判错，例如 `Forest ` 对应 `Forest .png`，`Forest.` 对应 `Forest..png`。

普通文件名中的 `< > : " / \ | ? *`、NUL 和 U+0001–U+001F 控制字符，以及 Windows 保留设备名等，属于不支持的名称形式。保留设备名规则包含附加扩展名的形式，例如 `NUL.png`，不通过大小写或加后缀绕过。具体首方列表与出处见本票补充事实；不做字符替换或自动重命名。

音频允许字面量 `%`、`#`，包括看似编码的 `%20`，按原始磁盘名称查询，不把原生请求 URL 的编码结果当成磁盘文件名。图片和影片首版均不支持名称中的 `%`、`#`；任何出现即为不支持形式，不区分百分号后字符，也不尝试 URL 解码、修复或搜索替代文件。图片原生反例和普通百分号成功样本均已留证；维护者选择统一排除以保持有限简单的支持边界。保存值及 helper 表达能力不变。普通使用报 error，候选／明确非活动保存配置按 ADR 0018 报 warning 并标明未检查；Asset Check Exception 不能豁免。这些是文件定位支持政策，不是编辑器 picker 或所有名称实际加载的验收结论。

### 4. 普通文件、链接与可读性

在支持的项目模式和名称规则下，**准确匹配且确认是普通文件即可判定存在**。不强制逐文件 open/close，不读取媒体内容，不检查大小、图像布局、解码或播放。0 字节文件仍可通过；元数据可访问但内容读取被拒绝时也可能通过。不存在“通过即保证可读／可播放”的承诺，也不增加可读性开关。

以已解析的真实 Project Root 为起点，保留根本身已有的符号链接／junction 别名与绑定规则。根以下素材路径的任一位置出现符号链接或 junction，就记录为不支持的链接形式，不继续访问其目标。指向根内、根外或已不存在目标的链接同样处理，不展开链接链。普通硬链接按普通文件处理，不判断其他共享路径。

所需目录实际为文件，或所需素材实际为目录等非普通文件，记录路径／文件类型不符合。权限或 I/O 错误导致无法枚举目录、辨认类型时记录为无法完成检查，不能推断文件缺失。单次查询内部矛盾时记录查询失败，不另做前后时点比较；本票不保证跨进程原子性，工作流票规定检查时点与整次操作处理。

### 5. System 加密标志

仅在存在相应类别的待检查素材使用时，解释必要的 `hasEncryptedImages` 或 `hasEncryptedAudio`；不扩大为所有 System 字段或无关类别的通用校验。读取哪一版 System 必须与工作流议题的其他标准输入一致。

| 相应标志 | 处理 |
| --- | --- |
| 缺失，或布尔值 false | 按普通文件规则检查 |
| 布尔值 true | 对相应类别记录不支持的加密素材模式，不因旁边存在普通文件而通过 |
| 存在但非 boolean（包括 null、数字、字符串等） | 必要项目字段无法解释，不采用原生 JS 真值转换来猜测 |

图片标志不影响音频和影片；音频标志不影响图片和影片；影片不受这两个标志控制。没有相应素材使用时不因本检查读取／校验该标志。

缺失／false 的普通模式下，只有 `Forest.rpgmvp` 而没有 `Forest.png`，仍是所需普通文件缺失。加密或其他格式文件若被观察到，只可作为解释线索，不是有效候选，也不要求主动审计部署输出。true 模式下不承诺部署文件检查、解密、密钥或图片例外支持。

### 6. 结果语义与来源

下表是必须区分的事实类别，不预先规定诊断代码、级别、展示方式或整体操作是否失败。

| 情况 | 结果语义 |
| --- | --- |
| 准确目标满足支持边界，元数据确认普通文件 | 文件存在；不等于运行时使用、内容可读或播放成功 |
| 无准确项，但有仅大小写不同的项 | 名称不匹配，保留发生的位置与相关项，不选替代 |
| 已确认类别目录不存在 | 缺失，并保留所需目录缺失这一原因 |
| 目录可检查但无所需文件，也无仅大小写不同项 | 文件缺失 |
| 路径或最终目标的类型已确认不符合 | 路径／文件类型不符合 |
| 不支持的名称、素材路径链接或加密模式 | 支持范围之外，保留具体原因；不伪装成文件缺失或通过 |
| 无法访问目录／元数据，或无法解释的 I/O 失败 | 无法完成检查，保留失败位置与原因 |
| 单次查询中事实矛盾，如枚举到的文件随即消失 | 无法完成该查询；不要求跨检查点比较，按查询失败诊断 |
| 字段合法地不指定素材 | 不产生文件查询，不构造空名 Asset Reference，也不制造缺失文件 |
| 固定标准数据条目缺失或引用无法解析 | 保留既有 Project Data Reference／依赖解析结果，不改称素材文件缺失 |
| 必需字段缺失、类型错误或必要字段无法解释 | 输入／数据解释问题，保留具体字段，不补空值掩盖 |
| 动态关系无法继续 | 保留事件内已知链和停止原因，不当成 None、文件缺失或检查通过；循环公共事件仅记录直接调用关系 |

合法 None、Compiler Default、标准关系与动态停止点沿用已定覆盖契约，不重新定义外部数据引用。只读取所需字段，不写入或修复依赖条目，不更改 DSL-Owned Project Data 的边界。

同一检查可复用同一目标的查询结果；每次 Event Asset Use、事件内 Asset Dependency Chain 及直接公共事件调用关系、事件／页／命令／路线／字段位置、原始名称及未启用／运行条件全部保留。正式 DSL、可识别 raw、直接与间接来源使用一致的文件规则；来源及确定性不会被查询去重抹掉。

### 7. 完成边界与下游交接

本票只确定文件定位、支持范围和事实分类，不实现扫描、修复、复制或重命名，不改写保存名称。成功只描述本次检查观察到的状态，不建立素材快照或跨检查有效性保证。

- [素材检查结果如何诊断并影响编译](04-asset-diagnostics-and-policy.md)负责 error／warning、默认开关、例外、聚合和编译影响，不能把本票“未通过文件判定”自动等同于阻断编译。
- [素材检查如何接入 Compile 与 Push 并保持结果有效](05-workspace-asset-check-lifecycle.md)负责标准字段版本（含加密标志）、单次素材门槛、每条新命令的当前查询及与编译输入保护／恢复的衔接；不因本票扩展素材复制或 Push 写入权限。
- [如何验收素材存在性检查并交接实施规格](06-asset-validation-acceptance.md)负责验收矩阵和实施规格交接。本票的源码核查、Windows 文档和 500 文件微测不是产品或原生加载验收，也不是 Node.js 22 下的性能承诺。

[ADR 0017](../../../docs/adr/0017-exact-asset-file-existence-in-editing-projects.md)记录严格名称匹配、普通项目支持范围与元数据存在性取舍。沿用 ADR 0016 的覆盖、ADR 0012 的原值保留与所有权边界；不重开 ADR 0013 的既有根绑定，工作流变化留给后续议题。本轮没有形成新领域术语，GLOSSARY.md 沿用现有 Asset Reference／Event Asset Use 等定义。

### 2026-10-24 — Q5 开销的本机只读微测与修订建议（未确认）
