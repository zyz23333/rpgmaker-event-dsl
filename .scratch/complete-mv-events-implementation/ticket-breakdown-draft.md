# MV 1.6.1 原生事件完整支持：已确认任务拆分

Review state: approved-and-published
Created: 2026-10-19
Source: [MV 1.6.1 原生事件完整支持实施规格](complete-mv-events-implementation-spec.md)

用户已确认本文件中的任务粒度、依赖和验收条件。55 张正式任务已按本地 tracker 约定逐票发布为 ready-for-agent，见[实施任务索引](tickets.md)。本文件保留已确认的拆分依据；任务的当前状态以独立文件为准。拆分发布时父规格保持不变；发布后的 Windows 平台调整见底部记录。产品实现与原生实验仍按任务推进。

## 拆分原则

- 当前支持与验收平台仅为 Windows / Node 22；Linux 等其他平台不纳入本阶段。
- 共 55 张：2 张证据/平台基础、8 张原生前置、5 张共享行为与引用上下文、7 张 Workspace 安全、3 张事件容器、22 张命令切片、8 张集成/原生回归/审计。
- 编号按依赖拓扑排列，不是强制串行队列。Blocked by 只列直接依赖；依赖全部完成才能领取整张票。原生前置按疑点拆开，没有把未相关的疑点合成一个全局阻塞。
- S5/S6 任务以完整安全写回作为可交付行为，因此整票依赖 22；规格允许的独立准备仍可先做，但不能据此签收整票。S2/S3 的最小行为使用当前可支持载体独立验证，不提前计作 S5/S6 或完整支持完成。
- 现有命令族责任边界足以承接改动，不另建宽泛预重构票。必要的小范围预重构放在对应最小行为票开头，保留该行为的可运行验证；不引入旧 API 兼容层或迁移说明。
- 每个原生事件族和移动码都有唯一主要责任票。共享保存外壳、参数契约和集成回归可以重复使用同一场景，但不能重复计算覆盖或以共享基础代替家族签收。
- 13、14、15 分别以 Loop、Movement Route 和 raw/Gate 行为建立共享能力；全部已知命令的参数完整性逐族补齐，48 统一审计，不能在基础票结束时冒称已支持全部模式。
- 每票的 E/R 关联只分配该组内与本票相关的代表场景，不要求每张票重复执行整个组。49–54 在最终集成候选上执行完整组；03–10 的原生事实采集不能代替产品输出验收。

## 统一验收要求

所有功能票均将以下要求连同本票专有验收点写入正式任务：

- 按规格 I1–I12 和对应完整参数附表实现；正式编写、编译、反编译、验证、已知 raw 及适用 Workspace 路径一起交付，实际发现并求值生成源码，预期独立于待测编译器。
- 对本票拥有的字段/模式/枚举/None/独立保存值/默认/正负边界及已知相互作用建案例；完整比较键存在性、数组长度/顺序、页序、值、镜像、CR 和非激活配置。
- 更新验收索引与关联执行结果；不把未执行、阻塞或缺环境记为通过。不修改已接受领域行为来迁就实现或测试，正常原生反例按既定流程回到相关决定。
- 产品变更执行 Windows / Node 22 全量适用检查与构建；安全票同时验证用户可观察的源码、项目、Snapshot、manifest、Discovery 集合和诊断状态。
- 本票分配的必要编辑器/游戏场景取得实际证据后才关闭；最终回归另外执行。原生版本、runtime/NW.js、步骤、输入身份、操作者、预期/实际与原始结果可追踪。
- 同步受影响的当前公开 API 文档、示例及编写指南；不保留旧 API 别名或迁移说明，不分发首方编辑器、runtime/源码或本地游戏资产。

03–10 为证据交付票：需要实际执行并记录结果，不必等待产品实现；契约反例未解决时，不将它标记为已解除实现前置。01–02 和 48–55 按各自基础/验收交付物签收。需要用户操作原生 UI 的具体步骤，沿用规格既定执行责任，不在本次拆分中虚构通过结果。
