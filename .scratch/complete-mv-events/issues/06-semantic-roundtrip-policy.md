## Question

前置资料：[MV 原生事件数据的完整边界与版本基准是什么](01-native-event-data-baseline.md)、[原生事件指令的参数与结构还存在哪些保真缺口](02-native-command-fidelity.md)、[编辑器如何保存分支与移动路线及不启用的字段](09-editor-serialization-evidence.md)、[原生事件属性的合法值与创建默认值是什么](10-editor-event-defaults-and-limits.md)。

与用户把“原生事件 decompile → compile → push 后语义等价”变为可判定契约：哪些字段和指令结构必须保持，哪些表示差异允许归一化，脚本文本、插件命令字符串、code 0、续行、默认值与无效但已有的数据如何处理。

分别决定未知命令、已知命令的异常参数、事件/页额外字段和非事件 carrier 字段的保留或拒绝方式。明确错误发生阶段、诊断位置和禁止静默丢失的保证，检查 raw fallback 与 Script Command Gate 的边界。

讨论的目标是有边界且可测试的数据契约，不是对任意 JavaScript 程序做不可判定的行为等价证明。现有 ADR 0003 将 decompile 定为 best-effort starting point；必须明确这次原生支持范围内保证如何收紧，是否需更新 ADR，而不把对非标准数据的能力说成完美往返。

### 成功判据与允许的表示差异

对支持范围内的 RPG Maker MV 1.6.1 原生事件，从同一 Project Data Snapshot 反编译，用户未修改 Decompiled Source 且所需配置、引用和同步前提满足时，compile → push 必须保持解析后的事件保存结构和值。包含字段存在性、非激活配置、页序和命令序、数组位置、显式空分支、字符串实际字符，以及编辑器读取的镜像和续行。只保持 runtime 行为不足以满足契约。

当前允许清单仅含 JSON 文本表示差异：排版、对象键顺序和等价字符串转义。固定默认的 DSL 省略与正常结构记录的重建必须恢复相同保存数据，并不是允许改动原始值或结构。未批准裁剪、填补原始缺字段、修复分支、清理 code 0、统一换行或选择某一份镜像。新增归一化必须单独列明条件、前后差异与依据。

此保证收紧 ADR 0003 对支持范围内原生事件的 best-effort 表述；整体 Workspace 工作流、按 Data Domain 所有权、完整 Compile Output、显式 Entry Identity 和既有 Push 安全机制不变。未知命令的原样保存不代表理解其执行语义，也不承诺任意 JavaScript 行为等价或任意非标准数据可接管。

### 数据处理矩阵

| 数据类别 | 处理契约 |
| --- | --- |
| 正式模型完整覆盖的原生事件及命令 | 使用正式 DSL，保存全部已确认状态；原生合法形态不能长期以 raw 代替实现 |
| 真正未知的事件命令 code | 外壳合法且所在列表可精确保持时，单记录 raw 保留并警告；参数作为未知 JSON 值不作私有语义推断 |
| 已知 code 的额外参数、未知参数模式、错误类型、范围外值或缺失正式实现 | 明确报错，不自动 raw；区分已证契约违反与尚未支持，正常原生反例须补正式模型 |
| 事件、页、条件、图像、路线等已拥有配置上的未知字段 | 拒绝；不新增通用 extraFields、raw page 或 raw event |
| 命令记录的额外顶层字段、缺必需字段或非法外壳 | 拒绝；不删字段、不跳记录、不以默认值替换 |
| 已知事件/页字段缺失、类型错误、未覆盖枚举、零页、null 命令列表及范围外值 | 拒绝；03/04/05 明确批准的保存例外与警告规则继续有效 |
| 未知移动子指令 | 自主移动保存路线及 Set Movement Route 均拒绝；不新增 raw movement command，也不以 raw 205 绕过路线校验 |
| 102/402 或 205/505 镜像矛盾、孤立续行、重复分支、闭合/缩进异常、非规范 Battle 组合 | 拒绝；不选一侧、不补齐、不删除，不拆成一串 raw 宣称保真 |
| 契约未覆盖的额外/中间/缺失/重复 event code 0 | 停止反编译；正常空体与结束记录由所属正式结构准确重建，路线终止另按路线契约判断 |
| 非 DSL-owned carrier 的未知有效 JSON | 从 Snapshot 按解析后的值完整保留；只检查安全定位/替换及所需引用的结构，不全面验证外部数据库或插件语义 |

### Raw DSL Command 与脚本边界

2026-10-19的[12号票Q1–Q7](12-native-saved-shape-model.md#answer)已最终确认Timer可选保存槽、逐类移动记录外壳及非空子体尾标记两态，该票已resolved且ADR0015已accepted。这些是有限正式模型增量，不是额外归一化许可。尤其endMarker表示所属子体最终保存结构；正式/raw合成后出现与声明矛盾或重复的本体尾标记须报错，但合法raw嵌套的内层标记不能误判为外层额外标记，不新增全局raw code0禁令。

Raw DSL Command 只承载一条事件命令的 code、indent、parameters；不新增 rawBlock 或 rawCommandList。code/indent 为非负安全整数，parameters 必须为严格可表示的 JSON 数组，不允许序列化静默改变无法表示的值。省略 indent 使用 DSL 父结构深度；显式 indent 为绝对值，不自动重缩进。反编译始终显式输出原始 indent，包括 0。Compile 对正式 helper 和 raw 共同生成的完整命令列表检查结构、缩进、分支、续行、镜像和结束记录。

手写 raw 的可识别原生类型、值域和 Project Data References 与正式表达执行相同校验及错误/警告等级，明确替换旧 raw 引用豁免。所有可识别原生 JavaScript 输入均受 Script Command Gate 约束，明确替换旧 raw Gate 豁免，包含嵌套体、续行、镜像和所有保存路线；空、不可达、非激活均不豁免。已知结构坏到无法判断时不因 raw 放行。未知代码与插件私有载荷不作语义推断，Gate 不是任意代码执行隔离机制。

Gate 关闭时允许反编译准确生成脚本并提示配置要求；Compile / Compile Check 必须阻止。反编译不自动开启 Gate，不通过改写为 raw 绕过。

### 文本记录映射

Show Text、Scrolling Text、Comment 的 lines 每项对应一条原生记录，元素内不得含 LF，CR 作为字面字符原样保留。Script 命令的 code 仅按 LF 分成 355/655，反编译仅在原生记录之间插入 LF。因此原生两条字符串 `"a\r"` 与 `"b"` 对应 `code: "a\r\nb"`，重新拆分后恢复同样两条记录。不得执行 CRLF→LF、CR→LF 或删除 CR。

这四类命令的单条原生文本记录内已含 LF 时，报告当前不能精确表达；不拆记录、不自动 raw。Show Text 1–4、Comment 1–6、Script 1–12 按原生记录计数，已有超长组按当前契约拒绝；Scrolling Text 至少一条、无已设上限。空字符串、空白和尾部空记录保留；不拆并指令组。该规则明确细化 05 的“不内嵌换行”，不套用到 note、Plugin Command Line 或脚本条件等单参数 Script Input。

CR 保存是明确的产品能力选择，未声称全部正常编辑器路径已验证。正常原生形态被排除的新证据须重开对应模型/限制，由 11 记录证据并建立明确决策依赖，不以 raw 遮掩。

### 阶段、诊断与失败边界

2026-10-19补充：[13号票Answer](13-native-value-domain-boundaries.md#answer)Q1–Q8及完整契约已最终确认，13已resolved。E101/E322的faceIndex与E201/202/203/285的direct x/y使用非负32位整数域并拒负零；当前素材/地图约束不修补保存值。Label/Jump、Name/Nickname/Profile及E111/E122/M45单参数Script槽按完整字符串原样保存，CR/LF仅按13的有限矩阵给参数重确认风险warning；既有四类行记录规则不变。正式编写、反编译及可识别raw执行同一域与诊断，不新增域外raw回退、素材扫描、默认或未知JSON通道。阶段与失败责任继续如下。

| 阶段 | 责任 |
| --- | --- |
| Decompile 发布源码前 | 验证可表达性、完整保存结构、字段和值域，以及完整候选声明加外部 Snapshot 已能确定的固定引用；不依赖偶然存在的手写源码补目标 |
| Compile / Compile Check | 基于当前 DSL、最终 Staged Data Graph 和配置重做全部校验，包含 raw、完整输出结构、引用和 Gate；保留既有保存 ID 例外及运行位置警告 |
| Push | 执行 Freshness、Drift、Destructive Change、Interrupted Push 等同步检查，不充当首次事件表达校验阶段 |

诊断包含稳定标识、阶段、严重级别、事件身份和精确数据路径，例如 `Map003.json#/events/7/pages/0/list/12/parameters/1`。报告预期/实际差异，字符串差异显式转义；镜像冲突同时给双方位置。Compile 提供 Definition Source、导出名和 DSL 内部路径，只在可靠时给源码行列。区分未知命令保留、未支持形态、契约违反、引用失败、Gate 阻止与发布失败；尽量汇总独立问题，但损坏区域不继续猜测而制造级联误报。

任意事件不能按契约表达则整次反编译失败，不支持跳过失败事件后仍成功。解析、校验或 I/O 发布失败不能留下可被 Definition Source Discovery 当成完整接管结果读取的部分新源码；原有源码和 Snapshot 保持原样，诊断报告可以保留。07 决定隔离发布、回滚或失败状态拦截机制。
