确定可发布的最小原生夹具及其来源、维护方式和首方参考资料缺席时的可重复验证方式；不将本地编辑器和游戏资产提交到仓库。最终产出应足以编写实施规格，但不在本票偷跑功能实现或把尚未执行的验收记为通过。

## Answer

用户于 2026-10-19 分三轮确认 Q1–Q12，随后回复“确认”，最终确认完整 Answer 与设计完成边界。本票已 resolved；以下为正式验收方案和实施依赖，不表示任何新增产品功能、自动化测试、真实编辑器或游戏场景已通过。

### 范围、完成门槛与独立依据

目标仍是 MV 1.6.1 的 Map Event、Common Event、Troop Event、完整原生页配置和 note、105 类事件指令及 45 类移动指令。参数、保存形态、值域、所有权与失败规则承接已解决前置票及 ADR 0008–0015，不以当前实现或旧测试限制新契约。

完整性按逐项契约覆盖衡量：事件字段、每种参数模式/枚举、保存形态、独立保存设置、默认/显式差异、适用边界、项目引用和 Script Command Gate 路径都有可追踪证据。独立取值不做无差别笛卡尔积；已知相互作用必须有组合案例。105+45 是库存索引，不是测试数量或完成证明；续行、镜像、分支、闭合与终止记录归入其父结构，不另算公开 helper。

预期结果独立于被测 compiler/decompiler。原生夹具保留原始捕获，合成样本以已决契约明确预期并注明来源。原生 fixture 经实际 Definition Source Discovery、Decompiled Source 求值、compile/check、diff、push 后，与原始数据比较完整解析结构和值。只允许既定 JSON 文本表示差异；不得过滤缺键/null/空数组、尾 0、镜像、非激活设置、CR、尾空行、未知字段，或裁剪坐标/归零索引后宣称无损。对明确拒绝负零的字段，应在会丢失符号的重写前验证拒绝行为。

编译器和反编译器互相往返只是证据之一；源码字符串包含 helper 名称、输出没有 raw、游戏行为相同，都不能单独证明保存结构正确。差异必须归因于实现、样本或契约；更新预期快照不能自行批准新行为。正常原生反例须重开相应模型，不能永久回退 raw、静默修复或重新归类为非法来通过。

实施切片在自身自动化及分配的必要原生检查通过后可分别合入；未完成的总体要求保留待验/阻塞。只有全部必验自动化与 E1–E7/R1–R7 的有效证据齐备，才可宣称完整支持。缺环境不豁免必验项。本票的完成仅表示方案已经确定、足以编写实施规格。

### 最小可发布夹具与采集纪律

发布自编事件的最小 JSON、解析和验证必需的最小自编项目上下文、合成支持/拒绝样本、来源与预期说明及临时工程复建步骤/工具。需要表现素材时优先自制可发布素材。普通自动化在没有本地 references 的情况下可完整执行；编辑器、首方 runtime 副本、本地游戏资产和原生源码不提交。

原生样本记录编辑器及 runtime 各自版本/哈希、操作路径、初始状态、输入/输出哈希与实际结果。首方文档、模板、既有保存样例、静态路径推导、明确产品支持的合成样本、合成拒绝样本、真实 UI 创建和游戏观察分别标注，不能混作同一种证明。原始保存数据先完整保留，再提取可发布的最小自编内容和上下文；来源与提取步骤必须可核对，不能因裁掉差异而提升证据强度。

“普通 UI 新建”“仅保存事件容器”“主动重确认参数”“游戏运行”是独立操作阶段。适用阶段分别记录；非典型支持值/结构以注入或合成起点标注，不要求伪造普通 UI 创建证明。重确认发生改写、拒绝或原生报错时保留前后数据与观察，不以新结果覆盖初始捕获，也不自动要求 DSL 模仿改写。

原生前置实验先核对可能推翻静态假设的移动外壳/indent/M0、403 与一项 Choices、子体尾 0、Timer Stop 槽、新建 Transfer/Shop/Battle 默认、脸图第三行与换小图、单槽字符串重确认及 EXP 临界输入。相关实现开始前取得对应结果；规格可先起草，无依赖工作可继续。其他原生检查随各自切片验收。

### 环境、责任与 Workspace 安全证据

普通自动化采用 Linux 与 Windows / Node 22，CI 增加 Windows。Windows 特有的路径别名/junction、目录发布、锁和文件替换有明确必验项；未经测试的平台不新增承诺。原生编辑器使用[已有身份记录的本地 MV 1.6.1](../research/editor-serialization.md#目标身份与版本)，游戏使用已标识的本地 1.6.1 runtime/NW.js，二者版本与哈希分别记录，全部在独立临时工程进行。已有文件或 PE/runtime 自报版本不是实际可运行及验收通过证明。

代理负责夹具、自动化、实验准备、可执行操作和证据整理。原生界面有可用控制能力时由代理操作；受工具限制的具体步骤由用户执行，代理提供步骤并整理原始结果。受限必验任务保持待执行或阻塞，不用推导代替观察。

安全验证保留预造 pending 状态的恢复测试，增加确定性故障注入与真实临时文件系统/受控多进程两层。覆盖如下失败边界，并断言原源码、项目文件、Snapshot、manifest、发现集合及诊断状态，而非只断言抛错：

- 输入捕获/发布期间源码、类型依赖、配置、Snapshot 文件集合与内容变化；哈希对应实际使用字节；缺失/旧契约版本、切换 Project Root Binding、pending 目标不符。
- Decompile 候选生成/校验/发布失败、宽 glob、别名/junction、隔离/最终位置解析差异、漏选文件、身份冲突、目标已存在或被抢占；未完成批次不可发现，原源码/Snapshot 保持；发布完成后未报成功的重试不覆盖目录。
- Compile/Check 同规则完整输出验证；Check 不发布/改状态；校验失败无发布；generated/manifest I/O 失败后的状态被 Diff/Push 拒绝，重编译可恢复。
- 全 Standard Project Data Snapshot 集合的改动/缺失/MapInfos 登记变化与 no-op Push；插件文件和未登记地图排除；写入/备份仍限 Affected 文件。Push 写前、逐替换、写后检测分别覆盖，后置失败保留 pending，不吸收外部改动或盲目回滚。
- 恢复的全 generated、全 snapshot、mixed/missing/unknown、元数据矛盾、目标不匹配与未知 pending 格式；旧契约收尾不变成当前 fresh，恢复后的外部新漂移仍拒绝新写。
- 同 Workspace 各命令（含 Check/Diff）互斥、即时报忙、进程中断、崩溃锁清理不解除 pending；不同 Workspace 或外部编辑器仍由检查点发现变化，不宣称全工程原子隔离。

检查点接口或子进程控制方式由实施者决定，不要求公开测试 API；适用必验项不得静默 skip。上述各项完整细则沿用 Workspace 集成 Answer，不在本票另改恢复或发布语义。
