# 05: 把共享逻辑错误定位到具体定义和调用位置

**What to build:** 共享模块或函数出现问题时，作者可以从公开诊断找到出错的共享定义、相关调用链和具体受影响事件。相同片段被多次复用时，每个使用位置保留正确来源，不会被最后一次调用覆盖。

Blocked by: 02
Status: ready-for-agent

Parent: [跨事件的共享编写模块与参数化命令函数（第一版）](../shared-authoring-modules-spec.md)
User Stories: 17, 19, 20, 21

- [ ] 导入解析、缺失导出、语法和类型错误保留实际问题模块及可靠行列；导入失败能找到发起导入的位置，不能仅报告最终事件入口。
- [ ] 共享函数求值或 DSL 构造错误关联共享定义与调用位置；参数类型错误定位到相应源码，运行到受限求值阶段的参数/构造问题能够关联实际调用。
- [ ] 跨两个及以上共享函数的嵌套组合保留可读且有用的调用链，能够从事件使用位置追溯到失败定义；不把内部加载器栈当成作者的调用链。
- [ ] 组合后发生的事件上下文、项目引用或素材验证问题保留原有阶段、严重性和含义；已知时报告 Entry Identity 和 DSL/native 路径，并关联可靠的共享定义和使用位置。
- [ ] 同一个共享对象被两个事件复用，以及在同一事件两个命令位置复用时，各次使用的来源均正确；不能依赖单个对象上最后写入的位置，也不能因素材诊断分组丢失受影响使用位置。
- [ ] 常量命令片段、直接函数调用和嵌套函数调用均有代表性来源案例。来源处理不改变生成数据、Native Saved Shape、验证结论或其他调用的参数。
- [ ] 身份或源位置尚不能可靠确定时明确保留未知，不伪造行号、事件身份或参数字段的精确来源；可可靠报告的定义和调用位置仍应显示。
- [ ] 通过公开 Compile/Check 的错误或警告验收，覆盖构造阶段失败、调用问题以及至少一个组合后引用问题和一个素材问题；测试检查实际源位置与受影响事件，不断言内部来源容器或对象身份。
- [ ] 保持已有内联源码、Common Event 调用和无共享函数时的诊断可用；失败路径及 Compile Check 仍遵守既有状态保护。
- [ ] 同步如何阅读共享定义与调用位置的使用说明，完成受影响的类型、静态和行为检查；仅当实际改变编译契约所定义的语义时按现有规则更新 Compile Contract Version。

本票在 02 已有本地和跨模块函数组合上完成逐次来源诊断。使用最小 Common Event 等公开工作流案例即可验收，不依赖 03 的容器矩阵或 06 的 Decompile 扩展；最终整合由 07 核对。
