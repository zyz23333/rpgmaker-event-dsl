# 03: 在三类事件和嵌套命令体中复用共享逻辑

**What to build:** 作者能把同一共享片段或参数化命令函数用于 Map Event、Common Event、Troop Event，以及分支、选项和循环的 Child Command Body。编译结果保持正确 Native Saved Shape，验证按每个使用位置的事件上下文进行。

Blocked by: 02
Status: ready-for-agent

Parent: [跨事件的共享编写模块与参数化命令函数（第一版）](../shared-authoring-modules-spec.md)
User Stories: 7, 10, 11, 12, 13, 27

- [ ] 为 Map Event Page、Common Event 和 Battle Event Page 分别提供一个真实 Workspace 成功案例，使用共享命令值或参数化函数生成内容，并核对独立预期的事件数据。
- [ ] 在条件分支、选项分支和循环体中组合共享片段与事件独有命令；验证作者指定的次序、缩进、分支关闭记录、完整事件终止记录及相关 Body End Marker 保存状态。
- [ ] 同一共享数组或命令对象在同事件两个位置、多个事件及不同嵌套深度使用时，各位置生成正确数据；不同参数调用不互相污染。仅比较保存结果，不把对象引用是否相同当作契约。
- [ ] 共享与手工展开写法具有相同 Native Saved Shape；测试以独立预期为主，两种产品路径互相比对只作补充，不归一化保存值或删除必要原生记录。
- [ ] 验证代表性的上下文不合法使用仍产生原有级别和含义的诊断；共享代码所在文件不替代调用事件的地图、战斗或角色上下文。
- [ ] 共享片段中的既有 Common Event DSL Command、引用解析和受 Script Command Gate 约束的输入保持原有规则；不能因为从函数返回就绕过验证。
- [ ] 通过公开 Compile/Check 验证嵌套组合，并对代表性成功结果完成 Diff/Push，确认写入的项目数据与生成结果一致；失败及 Check 路径保持既有只读和发布规则。
- [ ] 修复该矩阵暴露的组合、上下文或保存形态问题，保留相关既有事件族回归；不把所有 MV 命令重新做完整原生游戏验收作为本票条件。
- [ ] 完成受影响的类型、静态及行为检查；如修复改变类型、校验、默认或输出语义，按现有规则相对实际集成版本更新 Compile Contract Version。

本票验证和完善事件容器中的可用行为。诊断的逐次源码来源由 05 独立负责，不因此增加 05 对本票的阻塞关系；两票均须保留已经正确的事件身份和路径诊断。
