# Keep asset-check findings explicit while allowing narrow authoring exceptions

Compile, Compile Check and Push apply the same asset policy. Confirmed missing paths, case mismatches and wrong types block ordinary explicit uses, and warn for Conditional Asset Candidates or explicitly inactive saved configuration. Unsupported names, asset-path links and encrypted modes also warn for those candidates or inactive settings, with an explicit unchecked-coverage result; ordinary uses still error. A warning never proves existence or expands the file support in ADR 0017. Necessary field/reference failures, inaccessible metadata and an inconclusive individual query remain errors for every use. Existing structure validation and the Script Command Gate are unchanged.

An Asset Check Exception applies to one exact namespace and original name, with a required reason, and can downgrade only confirmed missing-path, case-mismatch or wrong-type errors. It retains facts, reasons and every event-local use. Unsupported forms cannot be waived: their severity comes from the use's candidate/inactive status, not the exception. No global off switch, global warning mode, wildcard or location-specific exception is added. Invalid or duplicate entries fail configuration validation; an entry that downgraded no error warns when its effect is determinable. Incomplete checking must not produce a false ineffective-exception finding.

Grouped presentation keeps each real occurrence, its event-local Asset Dependency Chain, conditions and direct Common Event call sites under ADR 0016; caller paths do not multiply use counts. Groups take the highest effective severity. Independent safe checks continue after errors. Coverage and operation success remain separate: a supported dynamic stop or an unsupported-form warning may leave a named part unchecked while the operation succeeds. An actual query failure still blocks. An item disappearing between enumeration and metadata inspection is an inconclusive query, not proven stable absence; this does not require comparing observations across workflow checkpoints.

On 2026-10-25 the user requested simplification of the originally accepted 2026-10-24 policy. We removed unconditional blocking of unsupported forms in candidates/inactive settings because a checker limitation need not prohibit preserving such saved state. We also removed cross-checkpoint observation-change errors and all-path provenance under the revised ADR 0019/0016. The detailed current policy is [ticket 04](../../.scratch/asset-validation/issues/04-asset-diagnostics-and-policy.md#answer). Compile errors prevent new publication, Check is read-only, and Push checks assets before writing without making later asset changes a recovery condition. No product implementation or executed acceptance is claimed.
