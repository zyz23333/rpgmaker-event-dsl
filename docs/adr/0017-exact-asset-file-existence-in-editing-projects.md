# Match exact asset files in ordinary editing projects

Event Asset Uses selected by [ADR 0016](0016-event-rooted-asset-use-coverage.md) need a file contract that does not inherit an unstated host filesystem or media capability. We choose the ordinary Windows / RPG Maker MV 1.6.1 editing Project Root, exact category-directory and filename spelling, and one appended desktop extension: `.png`, `.ogg`, or `.webm`. This is deliberately stricter than typical Windows case-insensitive lookup: names are not trimmed, normalized, URL-decoded, or repaired, and another format cannot substitute for the required file. Direct, recognized raw, and indirect uses share the same rules while retaining each origin. The detailed contract is in [the asset file existence decision](../../.scratch/asset-validation/issues/03-asset-file-existence-contract.md#answer).

The supported names are single filename components subject to ordinary Windows filename rules. Audio names may contain literal percent and hash characters. Image and movie names containing either character are outside the first-release support boundary. Native MV 1.6.1 observations showed that `literal%20image` and `image#hash` did not locate their same-named files, although an ordinary percent image did; the policy excludes the whole image percent/hash class instead of claiming every such name fails in MV. The [original observations](../../.scratch/asset-validation-implementation/evidence/01-native-media/observations.md) and [policy reconciliation](../../.scratch/asset-validation-implementation/evidence/01-native-media/policy-resolution-2026-11-02.md) preserve both counterexamples and successful samples. Asset paths below the resolved Project Root do not follow symlinks or junctions, including links within the root. Existing Project Root aliases and binding remain supported, and hard links retain ordinary-file semantics. Deployment trees and encrypted modes are outside support; missing or false encryption flags permit ordinary checking, true affects only the corresponding used category, and a present non-boolean flag is an uninterpretable necessary field. These boundaries keep the file lookup finite without changing saved values.

Existence requires an exact ordinary-file match and observable metadata, without opening or reading the media. We accepted the loss of content-readability detection to keep the check focused on presence and avoid additional open/close cost; a local 500-file probe showed substantial first-pass variation and is not a performance guarantee. Empty files or files whose contents cannot be read may therefore pass. Missing paths, case mismatches, wrong file types, unsupported forms, and access failures or observed changes remain distinguishable, as do legal absence and failures to resolve project data or necessary fields. None of these facts determines diagnostic severity or promises decoding, playback, or continued existence.

The user confirmed Q1–Q9, including the revised metadata-only Q5, and the consolidated contract and ticket completion boundary on 2026-10-24. This ADR is accepted. It preserves [ADR 0012](0012-event-saved-state-roundtrip-boundary.md)'s saved-value and ownership rules and does not change [ADR 0013](0013-bind-generated-data-to-compilation-assumptions.md)'s Project Root Binding. Diagnostic policy and explicit exceptions were subsequently accepted on the same date in [ADR 0018](0018-asset-check-diagnostics-and-explicit-exceptions.md), and lifecycle rules in [ADR 0019](0019-asset-checks-at-workflow-boundaries.md). Necessary standard-data fields, including applicable encryption flags, use the coherent captured snapshot; each operation obtains live-file observations at its gate under the 2026-10-25 revision of ADR 0019. There is no cross-checkpoint observation comparison; an individual query that cannot establish a supported file fact remains inconclusive. ADR 0018 separately permits unsupported-form warnings with unchecked coverage for inactive settings without changing these matching rules. These observations do not enter persistent Compile Baseline or extend the claim beyond the stated check points. At the original design handoff no product implementation or native acceptance had been claimed; later native observations are linked below.

The 2026-11-02 scope reduction in ADR 0016 defers initial/default candidates and caller reporting; it does not relax these file-matching or metadata rules for retained uses.

On 2026-11-03 the maintainer reaffirmed the image percent/hash restriction after reviewing the native counterexamples against the simplified specification. This amends the earlier design-stage assumption that image names could be checked as literal files. Audio literal-name support and the original saved values remain unchanged. The supported N02 cases are Chinese and space names across media, plus audio percent/hash; excluded image samples remain historical observations, never recast as successful native checks.
