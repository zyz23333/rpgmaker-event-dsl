# Match exact asset files in ordinary editing projects

Event Asset Uses selected by [ADR 0016](0016-event-rooted-asset-use-coverage.md) need a file contract that does not inherit an unstated host filesystem or media capability. We choose the ordinary Windows / RPG Maker MV 1.6.1 editing Project Root, exact category-directory and filename spelling, and one appended desktop extension: `.png`, `.ogg`, or `.webm`. This is deliberately stricter than typical Windows case-insensitive lookup: names are not trimmed, normalized, URL-decoded, or repaired, and another format cannot substitute for the required file. Direct, recognized raw, and indirect uses share the same rules while retaining each origin. The detailed contract is in [the asset file existence decision](../../.scratch/asset-validation/issues/03-asset-file-existence-contract.md#answer).

The supported names are single filename components subject to ordinary Windows filename rules; image/audio names may contain literal percent and hash characters, while movie names with those characters are outside support because the native movie path is assembled without the same encoding. Asset paths below the resolved Project Root do not follow symlinks or junctions, including links within the root. Existing Project Root aliases and binding remain supported, and hard links retain ordinary-file semantics. Deployment trees and encrypted modes are outside support; missing or false encryption flags permit ordinary checking, true affects only the corresponding used category, and a present non-boolean flag is an uninterpretable necessary field. These boundaries keep the file lookup finite without changing saved values or claiming native loading has been verified.

Existence requires an exact ordinary-file match and observable metadata, without opening or reading the media. We accepted the loss of content-readability detection to keep the check focused on presence and avoid additional open/close cost; a local 500-file probe showed substantial first-pass variation and is not a performance guarantee. Empty files or files whose contents cannot be read may therefore pass. Missing paths, case mismatches, wrong file types, unsupported forms, and access failures or observed changes remain distinguishable, as do legal absence and failures to resolve project data or necessary fields. None of these facts determines diagnostic severity or promises decoding, playback, or continued existence.

The user confirmed Q1–Q9, including the revised metadata-only Q5, and the consolidated contract and ticket completion boundary on 2026-10-24. This ADR is accepted. It preserves [ADR 0012](0012-event-saved-state-roundtrip-boundary.md)'s saved-value and ownership rules and does not change [ADR 0013](0013-bind-generated-data-to-compilation-assumptions.md)'s Project Root Binding. Diagnostic policy and explicit exceptions were subsequently accepted on the same date in [ADR 0018](0018-asset-check-diagnostics-and-explicit-exceptions.md), and lifecycle rules in [ADR 0019](0019-asset-checks-at-workflow-boundaries.md). Necessary standard-data fields, including applicable encryption flags, use the coherent captured snapshot; each required check point obtains new live-file observations. Relevant changes concern exact matching, necessary path types/links, queryability, and failure location, not content, timestamps, size, file identity, or unrelated directory entries when existence facts remain the same. These observations do not enter persistent Compile Baseline or extend the claim beyond the stated check points. No product implementation or native acceptance is claimed.
