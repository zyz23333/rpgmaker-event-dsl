# Preserve native command state while separating validation from execution guarantees

The formal Event DSL models native command parameters and saved structures, including empty branches, significant plugin-command whitespace, and saved choice positions that exceed the current number of choices. Parent commands own their continuation records and editor mirrors. Compilation preserves explicitly authored state and uses documented fixed defaults; it does not imitate editing actions that trim, replace, or discard saved values. This makes the command contract suitable for both deliberate authoring and native data takeover.

We distinguish malformed command input and unresolved Project Data References from uncertain runtime behavior. Invalid shapes, mutually exclusive parameters, confirmed value-range violations, missing project targets, and disallowed Script Input fail validation. Supported native commands remain expressible when their visible context suggests they will do nothing, select no object, or stall; those cases produce specific warnings. We do not require Common Event context declarations or whole-program call analysis, because definition location does not determine every later runtime context. The stricter enabled Battle Page Condition rules in ADR 0010 remain page-condition rules, not implicit restrictions on all command selectors.

An unnamed System Variable Slot or System Switch Slot remains addressable by explicit ID within the generated system capacity. A reference does not create a slot or restore a snapshot name. This clarifies ADR 0004's name-removal behavior without changing Definition identity or domain ownership.

Native absence is represented at the command parameter that supports it, with a field-specific encoding and with independent saved settings retained. It is not an empty-named Asset Reference, a universal stop or erase operation, or permission for unresolved project references. Change Equipment uses a Runtime Selector for its equipment ID because the actor's slot determines the database category at execution time; freezing that category from initial project data would change the native command's meaning.

This choice preserves state that a cleaner authoring-only model might discard, while accepting that validation cannot prove execution will succeed. Formal authoring still has explicit parameter ranges and structural requirements; runtime tolerance alone does not establish support. The full command inventory requires a [parameter evidence table](https://github.com/zyz23333/rpgmaker-event-dsl/blob/98ad17b61371e349e09719009204e29264b16f1b/.scratch/complete-mv-events/issues/11-native-command-parameter-evidence.md) before the implementation specification is complete, and representative editor and game checks remain separate evidence.

On 2026-10-19 the user accepted [ticket 13](https://github.com/zyz23333/rpgmaker-event-dsl/blob/98ad17b61371e349e09719009204e29264b16f1b/.scratch/complete-mv-events/issues/13-native-value-domain-boundaries.md#answer)'s Q1–Q8. Show Text and Change Actor Images include nonstandard face-image sizes reachable through the native picker. Their face indices and the direct coordinates of Transfer Player, Set Vehicle Location, Set Event Location, and Get Location Info use integers 0..2,147,483,647, rejecting negative zero as well as other out-of-domain inputs. This finite saved-value capability aligns with the target QML int type without claiming every value is ordinarily selectable or tested. Authoring, decompilation, and recognized raw parameters share these rules; other numeric fields and runtime variable values do not inherit the range.

The original decision excluded asset-file and dimension scanning. The accepted [ADR 0016](0016-event-rooted-asset-use-coverage.md) replaces the file-scanning exclusion with explicit event-rooted coverage, including selected inactive saved names and recognized raw inputs. Its 2026-11-02 revision retains direct fields and a smaller set of fixed standard-data relationships, with defining-event positions and local dependency chains; initial/default candidates and Common Event caller reports are deferred. [ADR 0017](0017-exact-asset-file-existence-in-editing-projects.md) keeps ordinary editing projects, exact desktop matching, explicit name/link/encryption boundaries and ordinary-file metadata without mandatory media opens. Under the current [ADR 0018](0018-asset-check-diagnostics-and-explicit-exceptions.md), confirmed file problems and unsupported forms warn for explicitly inactive settings (unsupported forms identify unchecked coverage), while ordinary uses error; necessary input and actual query failures remain errors, and narrow explicit exceptions can downgrade eligible confirmed file problems. [ADR 0019](0019-asset-checks-at-workflow-boundaries.md) preserves one current-file gate per Compile/Check or Push, coherent snapshot dependencies and independence from Generated Freshness and data recovery. Diff and takeover add no asset-file scan. Saved state is not repaired, asset dimensions remain excluded, and these design decisions do not claim implementation.

A non-None face index of at least 8 warns that it exceeds the official two-row layout and its asset dimensions are unchecked; it is not declared invalid. None retains its independent in-domain index without missing-image or image-bounds warnings. Direct coordinates outside a fixed target map's snapshot bounds warn and remain unchanged, while missing fixed map references fail. Commands using the current map receive only conditional warnings from their containing Map Event, without treating that location as proof of all future execution contexts; an unknown map alone does not produce a warning. Map Event initial placement keeps its separate bounds rule. Change EXP constants use 1..9,999,999, retaining the conflicting help text and required real-editor check. The user confirmed ticket 13's complete contract and completion boundary on 2026-10-19; the ticket is resolved. Implementation and native acceptance remain separate work.

Later on 2026-10-19, implementation ticket07 traced the editor's empty Shop reload and tail-addition path, which retains a structural zero-ID row beside real goods. The user explicitly accepted the finite Shop Goods Placeholder variant `{kind:"placeholder"}`: it encodes only the exact four goods slots `[0,0,0,0]`, may appear at any position, and preserves order and repetitions. An empty goods list still emits the unique placeholder; decompilation of that sole exact placeholder canonically returns `goods:[]`. Real item/weapon/armor goods still require valid positive-ID references; other zero-ID combinations, extra placeholder fields, and standard mode0 with a nonzero price value remain rejected. This amends the former prohibition on mixed placeholders, without broadening price or reference domains.
