# Check event asset uses through explicit native relationships

RPG Maker MV's deployment collector scans selected fields across whole databases and deduplicates names to filter existing files for copying. We choose all current Event Definitions as the roots of file-existence checking, following an explicit finite set of native event and standard project data relationships. This limits unrelated project diagnostics and makes each checked name explainable. Selected saved names remain in scope when their configuration is inactive; native directory selection and execution conditions remain explicit. The detailed coverage is recorded in [asset-validation ticket 02](../../.scratch/asset-validation/issues/02-direct-asset-reference-coverage.md#answer).

Each Event Asset Use retains its own origin and Asset Dependency Chain even when file queries or called-event results are reused. Native command mirrors represent one logical use. Known initial or fallback names may be Conditional Asset Candidates, while unresolved runtime targets end the affected path without implying no dependency. Selected Common Event relationships preserve call sites and stop expansion at cycles. We do not infer current state from preceding commands or extend the selected relationships into whole-database, plugin-declaration, engine-hardcoded-resource, or general runtime-side-effect analysis. Reading external asset fields does not change data ownership or authorize rewriting them.

The user accepted the component decisions Q1–Q14 and confirmed the consolidated contract and ticket completion boundary on 2026-10-20. Ticket 02 is resolved and this ADR is accepted. This coverage decision replaces ADR 0011's blanket exclusion of asset file scanning with the selected event-use scope, while retaining its dimension boundary and distinction between saved validation and execution guarantees. It preserves ADR 0012's saved-state and recognized-raw rules. File matching was subsequently accepted on 2026-10-24 in [ADR 0017](0017-exact-asset-file-existence-in-editing-projects.md), followed by diagnostic severity and explicit exceptions in [ADR 0018](0018-asset-check-diagnostics-and-explicit-exceptions.md). The same day's accepted [ADR 0019](0019-asset-checks-at-workflow-boundaries.md) supplies coherent standard-data inputs, live asset checks at compilation and Push boundaries, and the separation from persistent Generated Freshness. Push reconstructs the same selected uses from current generated event state and its corresponding snapshot, preserving origins without expanding roots or ownership. These are design contracts, not implementation or runtime-verification claims.
