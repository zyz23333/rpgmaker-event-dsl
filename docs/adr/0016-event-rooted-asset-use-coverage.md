# Check event asset uses through explicit native relationships

We choose all current Event Definitions as independent roots of file-existence checking, following the finite native event and standard-data relationships in [ticket 02](../../.scratch/asset-validation/issues/02-direct-asset-reference-coverage.md#answer). This finds direct and selected indirect assets without scanning unrelated databases. Saved names remain in scope when inactive; native directory selection, Conditional Asset Candidates and execution conditions remain explicit. Reading external fields does not expand DSL-Owned Project Data.

Each Event Asset Use retains its defining event, native saved position and the Asset Dependency Chain from that event's operation to its asset-bearing field. Different real fields, commands, members, timing entries and slots remain separate uses even when the target filename is shared; native command mirrors remain one logical use. Every current Common Event is checked independently. Common Event commands and selected Skill effects retain each direct call site and target, including the Skill/effect path when applicable, but do not duplicate the called event's uses or concatenate every transitive call path. Use counts describe those event-local occurrences, not the number of possible caller paths. Cyclic call relationships are finite edges; they require no recursive asset expansion or separate cycle diagnostic. Dynamic targets still retain their known origin and reason for stopping.

The user requested this simplification on 2026-10-25 after reviewing overdesign. It replaces the 2026-10-20 requirement to expand every bounded caller chain: even an acyclic graph can have exponentially many paths, while all Common Events are already independent roots. Definition locations and direct callers retain actionable provenance without that cost. The selected asset fields, runtime-unknown boundaries and exclusions remain unchanged; we do not infer state from preceding commands or add whole-database, plugin, hardcoded-resource or general runtime-side-effect analysis.

This revises ADR 0011's former exclusion of file scanning while preserving ADR 0012's saved-state and recognized-raw rules. [ADR 0017](0017-exact-asset-file-existence-in-editing-projects.md), [0018](0018-asset-check-diagnostics-and-explicit-exceptions.md) and [0019](0019-asset-checks-at-workflow-boundaries.md) define matching, policy and workflow. Push reconstructs the same event-local uses and direct call relationships from verified generated events and their corresponding snapshot. These are design contracts, not implementation or runtime-verification claims.
