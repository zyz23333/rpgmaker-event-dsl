# Preserve event saved state across the ownership boundary

Event Semantic Round Trip is judged by saved event structure and values, including inactive settings and editor-facing data. Equivalent runtime behavior alone is insufficient. With unchanged Decompiled Source and satisfied configuration, reference, and synchronization requirements, supported native event data must be reconstructed through compilation and synchronization; JSON textual representation may change, while every additional normalization needs an explicit agreed rule. This tightens ADR 0003's former best-effort starting-point contract within the supported native event scope, without promising arbitrary program equivalence or universal nonstandard-data support.

The first version rejects unknown fields inside owned events and page configuration rather than silently removing them or introducing generic extra fields, raw pages, or raw events. This deliberately limits takeover of some plugin-extended events in exchange for keeping the authored event state explicit. Unknown valid JSON outside DSL-Owned Project Data is carried from the Project Data Snapshot without interpretation; validation examines only the structure needed for safe replacement and required project references. This follows the domain ownership boundary in ADR 0003 and the troop carrier boundary in ADR 0010.

Raw DSL Command remains a single-record escape hatch for code, indentation, and JSON parameters. Extra top-level command fields are rejected, and this version does not add raw blocks or raw command lists. Automatic raw fallback is limited to genuinely unknown command codes with valid record envelopes and a preservable surrounding structure; it warns that the payload is uninterpreted. Known native command anomalies and missing native helper implementations are reported rather than downgraded. Handwritten raw records also retain normal validation of recognizable native parameters and project references, explicitly replacing the former raw reference exemption.

Conflicting choice or movement-route mirrors, unsupported command-list structures, and malformed known event configuration are rejected without choosing a preferred copy, repairing records, or filling missing saved fields with Compiler Defaults. Normal terminators and empty-body markers must reconstruct exactly through their owning formal structures. An unsupported form is distinguished from a proven contract violation; evidence that it is a normal native form must reopen the formal model rather than justify permanent raw fallback.

Unknown movement instructions are rejected consistently in Autonomous Movement and Set Movement Route, without adding a raw movement instruction or wrapping a known route command in raw to bypass inspection. Raw event records retain explicit absolute indentation, while omitted authored indentation follows the DSL parent; decompilation always writes the original indentation explicitly. Compilation validates the complete emitted list, including mixtures of formal helpers and raw records, so local validity does not excuse invalid surrounding structure.

Line-record commands use LF as their separator and preserve CR as a literal character. Script command text splits only on LF and decompilation inserts LF only between records; no CR or CRLF normalization is allowed. An individual native text record containing LF cannot be expressed through the selected line model and is rejected, as are groups outside the agreed record-count limits. This resolves ticket 05's deferred text mapping without claiming that every supported CR-containing state has been observed in the editor.

The Script Command Gate applies at compilation to recognizable native JavaScript-bearing inputs in both formal commands and raw records, including saved nested routes and continuations. This explicitly replaces the former raw exemption; it is not a claim to understand arbitrary plugin execution. Decompilation may express scripts while the Gate is closed and report the configuration needed for compilation, without changing the configuration or changing representation to evade the Gate.

Because DSL-Owned Project Data is taken over as a whole, a failed decompilation must not leave partial new source that Definition Source Discovery can treat as a complete takeover. Existing source and the Project Data Snapshot remain intact; diagnostic reports may be retained. [ADR 0014](0014-publish-decompiled-source-as-a-complete-directory.md) supplies the accepted Workspace mechanism: an undiscoverable complete candidate batch, pre-publication discovery and identity checks, and a single non-overwriting directory publication, including the I/O failure boundary.

Before source publication, decompilation validates expressibility and all fixed references determinable from its complete candidate declarations and external snapshot data. Compilation and Compile Check independently revalidate the current Staged Data Graph and configuration. Diagnostics distinguish unsupported forms from contract violations and include stable identifiers, stage, severity, event identity, precise native or DSL paths, and related locations for conflicts. Source line numbers are supplied only when reliably known.

On 2026-10-19 the user confirmed [ticket 12](../../.scratch/complete-mv-events/issues/12-native-saved-shape-model.md#answer)'s bounded saved-shape additions, including a single optional trailing Body End Marker in an otherwise valid nonempty child body. This explicitly extends formal expressibility without adding normalization or generic extra fields; ordinary UI creation of the marker-absent body is not claimed. The final emitted list must agree with each formal body's declared marker state while preserving existing validation of legal handwritten raw combinations and nested boundaries. [ADR 0015](0015-bounded-native-saved-shape.md) records the accepted refinement and the ticket is resolved.

On 2026-10-19 the user accepted [ticket 13](../../.scratch/complete-mv-events/issues/13-native-value-domain-boundaries.md#answer)'s Q1–Q8. Label, Jump to Label, Change Name, Change Nickname, Change Profile, and the single-parameter Script Inputs in Conditional Branch, Control Variables, and Movement Routes preserve complete strings, including empty text, whitespace, CR, LF, CRLF, and trailing characters, without an additional product character-count or line-count limit. Authoring, decompilation, and recognized raw inputs use the same accepted domain. Script Command Gate, Plugin Command Line's existing contract, and the four line-record families above are unchanged.

Warnings identify parameter-reconfirmation risks without modifying saved text: LF in the listed single-line inputs, two or more LF characters in Profile, or CR in any of these listed strings. Counts use the original text, including trailing separators; CR warnings state that preservation needs native verification rather than asserting normalization. This does not simulate all Qt text behavior, promise JavaScript execution, or imply that merely saving an event container rewrites its contents. The finite numeric domains and context warnings in ADR 0011 likewise preserve accepted saved values without asset-dependent repair. The user confirmed ticket 13's complete contract and completion boundary on 2026-10-19; the ticket is resolved. No product, real-editor, or game acceptance is claimed.

The user also accepted implementation ticket07's finite Shop Goods Placeholder amendment on 2026-10-19 after a conditional normal editor code path contradicted the original mixed-placeholder prohibition. Each exact `[0,0,0,0]` goods record is owned by Shop and may be interleaved or repeated without losing its saved position or count; only a sole exact placeholder decompiles canonically as `goods:[]`, which reconstructs the same native record. The explicit `{kind:"placeholder"}` variant carries neither a Project Data Reference nor a custom price. Known raw Shop records receive the same exact placeholder and parent-owned continuation checks; other zero-ID forms and standard mode0 with nonzero price remain rejected. This is a finite formal expression of saved data, not permission to filter placeholder records, drop continuations, repair arrays or use permanent raw fallback. [Ticket07](../../.scratch/complete-mv-events-implementation/evidence/07-shop-defaults-and-goods-reverse.md#契约比较与已接受修订) retains the original counterexample, user decision and static-evidence limits; product roundtrip and game execution have not been established by that decision.
